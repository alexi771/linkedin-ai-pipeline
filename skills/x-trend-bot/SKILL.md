# Trend Bot: темы, которые повторяются у разных авторов X

Пайплайн: `~/linkedin/мониторинг.md`, раздел «Пайплайн контента на ботах». Механика (решение автора 23.10.2026): не считать заранее заданные темы, а собрать посты по ключам ниши и найти темы, которые сами повторяются у разных авторов. Если одну тему подняли несколько человек и вместе он набрала много отклика, это тренд.

## Что где лежит

| Что | Где |
|---|---|
| 20 ключей для поиска | `~/linkedin/тренды/ключи.json` |
| Собранные посты недели | `~/linkedin/тренды/raw/ГГГГ-ММ-ДД.json` (локально, в git не идут) |
| Посты списка swipe от бота 1 | `~/linkedin/swipe/raw/ГГГГ-ММ-ДД.json` |
| Темы по неделям | `~/linkedin/тренды/история.json` |
| Позиционирование и рубрики | `~/linkedin/README.md` |
| Факты о автору | `~/linkedin/profile.md`, `~/linkedin/проверка-источников.md` |
| Сводка | `~/linkedin/тренды/ГГГГ-ММ-ДД.md` |

`ключи.json`: `{"ключ": {"рубрика": "...", "x": "запрос для X"}}`.
`история.json`: `{"ГГГГ-ММ-ДД": {"тема": {"authors": N, "posts": N, "likes": N, "keys": [...], "top": "..."}}}`.

## Правила

- Только чтение. Не нажимать Like, Repost, Follow, Reply и ничего в меню поста. Разрешено: открыть страницу, прокрутить, прочитать DOM.
- Пауза 2-3 секунды между прокрутками, прокрутка через JS (`window.scrollBy(0, 3000)`), один поиск целиком одним `browser_batch` (не больше 5 прокруток в пакете).
- Ответ `javascript_tool` обрезается около 2 000 знаков: копить посты в `window.__tr`, считать в странице, тексты забирать по 10 штук. Ссылки в тексте заменять на `[link]`.
- Чужие посты в сводку не копировать: первая строка дословно, остальное пересказом.
- Рынки и язык из `~/linkedin/README.md` (в образце: США и Китай, английский; русскоязычные посты пропускать).
- Время: весь прогон не больше 30 минут (Планировщик обрывает задачу через час).
- Пароль не вводить, капчу не решать. Нет входа в X: записать одной строкой в сводку и остановиться.

## Шаги

### 1. Браузер

Загрузить инструменты Claude in Chrome одним вызовом ToolSearch (`tabs_context_mcp`, `tabs_create_mcp`, `navigate`, `javascript_tool`, `get_page_text`, `tabs_close_mcp`, `browser_batch`, `computer`). Вызвать `tabs_context_mcp` с `createIfEmpty: true` и работать в своей вкладке.

### 2. Сбор постов по 20 ключам

Если `тренды/raw/<сегодня>.json` уже есть, прочитать его и пропустить ключи, которые там отмечены: так повторный запуск в тот же день продолжает, а не начинает заново.

Для каждого ключа один поиск во вкладке Top (самые сильные посты), за 7 дней:
`https://x.com/search?q=<encodeURIComponent(запрос x + " lang:en min_faves:50 since:<сегодня-7>")>&src=typed_query&f=top`

Подождать 4 секунды, собрать посты сборщиком, 3 прокрутки (около 20-30 постов). Сборщик:

```js
(()=>{window.__tr=window.__tr||{};const key=window.__key||'';
for(const a of document.querySelectorAll('article')){
  const tm=a.querySelector('time'); if(!tm) continue;
  const link=tm.closest('a')?.getAttribute('href')||''; if(!link) continue;
  if(window.__tr[link]){ if(!window.__tr[link].keys.includes(key)) window.__tr[link].keys.push(key); continue; }
  const n=id=>{const s=(a.querySelector(`[data-testid="${id}"]`)?.getAttribute('aria-label')||'');const m=s.match(/([\d.,]+)\s*([KMkм]|тыс|млн)?/);if(!m)return 0;let v=parseFloat(m[1].replace(/,/g,''));const k=(m[2]||'').toLowerCase();if(k==='k'||k==='тыс')v*=1e3;if(k==='m'||k==='м'||k==='млн')v*=1e6;return Math.round(v)};
  window.__tr[link]={author:link.split('/')[1],url:'https://x.com'+link,time:tm.getAttribute('datetime'),keys:[key],
    likes:n('like'),replies:n('reply'),reposts:n('retweet'),
    text:((a.querySelector('[data-testid="tweetText"]')||{}).innerText||'').replace(/https?:\/\/\S+/g,'[link]').slice(0,400)};
}
const v=Object.values(window.__tr);return v.length+' постов, авторов '+new Set(v.map(x=>x.author)).size})()
```

Перед каждым поиском выставить `window.__key='<ключ>'`. После каждого ключа дописать собранное в `тренды/raw/<сегодня>.json` (массив постов + список сделанных ключей), чтобы обрыв не потерял работу. Репосты и ответы не брать.

Добавить посты бота 1 за 7 дней из `swipe/raw/` (с ключом `swipe`). Дубли по ссылке склеить.

### 3. Группировка в темы

Прочитать все посты (обычно 300-500) и сгруппировать в темы. Тема это одна конкретная вещь, о которой говорят разные люди:
- событие или релиз с обсуждением («OpenAI запустил рекламу в ChatGPT в новых странах»);
- находка или данные («в Search Console появился отчёт по Gen AI»);
- спор или тезис («SEO умер / не умер из-за AI Mode»);
- приём или формат («показываю, как агент ведёт мой бизнес»).

Не тема: общее слово («AI», «SEO»), одиночный пост, реклама, розыгрыши, мемы без мысли.

Для каждой темы посчитать:
- **авторов**: разных аккаунтов (главная метрика);
- **постов**;
- **отклик**: сумма лайков, ответов и репостов всех постов темы;
- **ключи**, по которым тема нашлась (тема, найденная по 3+ ключам, пересекает ниши).

### 4. Что считать трендом

| Вердикт | Условие |
|---|---|
| тренд | 3+ разных автора и отклик от 1 000 |
| сильный тренд | 5+ авторов и отклик от 5 000 |
| на подходе | 2 автора или отклик 300-1 000: смотреть на следующей неделе |

Сравнить с `история.json` за прошлую неделю (похожая тема по смыслу, а не по точным словам):
- **новая**: прошлой недели не было;
- **растёт**: авторов или отклика больше, чем неделю назад;
- **держится** / **остывает**.

Новая или растущая тема важнее той, что держится третью неделю: в LinkedIn он ещё не надоела.

**В сводку идут только 3-5 трендов в неделю** (решение автора 23.10.2026): больше ему не нужно. Порядок отбора: новые и растущие, затем по числу авторов, затем по отклику. Темы, которые держатся с прошлых недель, в эти 3-5 не брать, если есть новые. Всё остальное только в `история.json`, в сводку не выводить.

Записать темы недели в `история.json`.

### 5. Идея поста

Для каждого из 3-5 отобранных трендов: тема поста в LinkedIn для автора по его рубрике (ИИ-поиск и GEO, ИИ-контент и инструменты, стартапы, Китай, путь) и факт из `profile.md` или `проверка-источников.md`, на который он опирается. Нет факта: «факта нет, спросить у автора». Если тема ложится на день из `план-постов-2-недели.md`, указать день.

Факт для LinkedIn без России: российские кейсы и площадки (Яндекс, Алиса, клиенты из РФ) не предлагать, рынки США и Китай. Посты, которые уже вышли (`~/linkedin/опубликовано.md`), не предлагать заново: такую тему давать как продолжение со своим углом. Урок первого прогона: одна идея опиралась на российскую площадку, другая повторяла уже вышедший пост.

### 6. Файл сводки

`~/linkedin/тренды/ГГГГ-ММ-ДД.md`:

```markdown
# Тренды X: ГГГГ-ММ-ДД

Неделя ДД.ММ-ДД.ММ. Собрано постов: N от M авторов по 20 ключам и списку swipe. Тем найдено: T, трендов: K, в сводке: 3-5.

| № | Тема | Авторов | Постов | Отклик | Ключи | Неделя к неделе | Вердикт |
|---|---|---|---|---|---|---|---|

## 1. Тема
- Кто поднял: @автор1 (лайки), @автор2 (...), @автор3 (...)
- Самый сильный пост: первая строка дословно, пересказ в одну строку.
- Идея для автора: ... (факт: ..., источник: ...)

## На подходе
Одна строка: 2-3 темы, за которыми смотреть на следующей неделе.
```

### 7. Конец

Закрыть свою вкладку. Ответить автору одной-двумя строками: сколько трендов, самый сильный (тема, авторов, отклик) и путь к файлу. При запуске по расписанию достаточно файла.

## Запуск по расписанию

Планировщик заданий Windows, задача «X trend bot», понедельник 7:00 (после бота 1 в 6:00), скрипт `~/linkedin/тренды/run-x-trend-bot.ps1`. Браузер Vivaldi, как у бота 1. Лог пошаговый (stream-json) в `тренды/logs/`.
