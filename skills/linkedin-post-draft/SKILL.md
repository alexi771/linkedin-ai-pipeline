# Черновик поста LinkedIn из голосового

Пайплайн: `README.md` репозитория. Это шаги 3 и 4 из пайплайна André Nogueira: Hook Writer и Drafter.

## Что где лежит

| Что | Где |
|---|---|
| Факты о автору (единственный источник) | `~/linkedin/profile.md` |
| Правила постов, позиционирование | `~/linkedin/README.md` |
| План постов: рубрика, первая строка, факты, цель дня | `~/linkedin/план-постов-2-недели.md` |
| Проверенные цифры с источниками | `~/linkedin/проверка-источников.md`, `artifacts-2026-10-22/` |
| Образец его голоса | тексты в `~/linkedin/опубликовано.md` |
| Идеи из X | последние файлы `~/linkedin/swipe/` |
| Черновики | `~/linkedin/черновики/ГГГГ-ММ-ДД-тема.md` (дата публикации) |

## Правила

- В посте только факты из `profile.md` и цифры с источником. Новый факт из голосового в пост не идёт, пока автор его не подтвердила; после подтверждения дописать его в `profile.md`.
- Рынки США и Китай. Российские кейсы и площадки (Яндекс, Алиса, клиенты из РФ) в LinkedIn не упоминать, даже если они есть в голосовом.
- Amazon только как остановка пути, не тема поста.
- Данные поставщиков подписывать как данные поставщиков («по данным Similarweb»).
- Без самооценок («я эксперт», «уникальный подход») и без объяснения читателю его же ниши.
- Не публиковать. Публикует Claude через браузер только после «да» автора на конкретный текст, отдельным шагом.

## Шаги

### 1. Получить текст

- **Аудиофайл** (ogg, m4a, mp3, wav, mp4): расшифровать локально, звук никуда не уходит. Запускать Python из окружения с faster-whisper с `PYTHONUTF8=1`:

  ```python
  import sys
  sys.path.insert(0, r"<путь к mcp-transcribe>\src")
  from server import transcribe_video
  transcribe_video("file", r"<путь к аудио>", r"<scratchpad>", model="small", language="auto", output_formats=["txt"])
  ```

  Расшифровку положить в scratchpad, не в репозиторий. Если текст вышел кашей, повторить с `model="medium"`.
- **Расшифровка или текст в чате**: взять как есть.

### 2. Понять, какой это пост

- Если автор назвал дату, взять строку этого дня из `план-постов-2-недели.md`: рубрика, черновая первая строка, факты, цель (репосты, комментарии, сохранения, лайки).
- Если даты нет, определить рубрику по смыслу (ИИ-поиск и GEO, ИИ-контент и инструменты, стартапы, Китай, путь) и предложить день из плана, где тема совпадает. Цель тогда комментарии.

### 3. Факты

Выписать из голосового все утверждения о ней и все цифры. Каждое сверить:

| Утверждение | Есть в profile.md? | Источник цифры | В пост? |
|---|---|---|---|

- Есть в профиле: в пост.
- Нет в профиле: в «Вопросы к автору», в пост не идёт.
- Внешняя цифра: только если есть в `проверка-источников.md` или в `artifacts-2026-10-22/`; иначе «источник не найден» и в пост не идёт.

### 4. 10 первых строк

Написать 10 вариантов первой строки разных типов: цифра, контраст «было / стало», факт из первоисточника, короткая история, спорный тезис, совет. Вопрос первой строкой не ставить.

Каждой поставить оценку 0-5, по одному баллу за:
1. Начинается с цифры, названия или конкретного факта.
2. Не длиннее двух строк на телефоне (около 110 знаков).
3. Есть конкретное слово: число, продукт, компания, срок.
4. Попадает в цель дня (репосты: факт, которым хочется поделиться; комментарии: спорный тезис; сохранения: обещание пользы).
5. Факт за строкой подтверждён (п. 3).

Показать все 10 с оценками, лучшие 3 сверху. Если в плане уже есть первая строка, он идёт одним из 10 вариантов и оценивается наравне.

### 5. Пост

По лучшей строке написать пост на английском:
- 900-1 300 знаков с пробелами;
- короткие абзацы по 1-3 предложения, стрелки → для списков, как в посте 22.10;
- в конце вопрос к читателю, на который отвечают из своего опыта;
- без ссылок в тексте: ссылка на источник уходит в первый комментарий;
- 0-2 хэштега в конце.

Голос сверять с текстами из `опубликовано.md`: «я» и свой опыт, без пафоса.

### 6. Humanizer

Прогнать текст через навык `humanizer`, не меняя фактов и цифр. После этого пересчитать знаки.

### 7. Самопроверка

- [ ] 900-1 300 знаков
- [ ] первая строка не вопрос
- [ ] у каждой цифры есть строка в таблице источников
- [ ] нет фактов вне `profile.md`
- [ ] нет России и российских кейсов
- [ ] нет ссылок в тексте, хэштегов не больше 2
- [ ] в конце вопрос

Что не прошло, исправить, а не отмечать.

### 8. Файл и ответ

`~/linkedin/черновики/ГГГГ-ММ-ДД-тема.md`:

```markdown
# Черновик: ГГГГ-ММ-ДД, рубрика

Из: голосовое / расшифровка / текст в чате, ГГГГ-ММ-ДД. План: строка дня (или «вне плана»). Цель: ...

## Первые строки
| № | Строка | Тип | Оценка |
|---|---|---|---|

## Пост (N знаков)
...

## Первый комментарий
Source: ...

## Источники
| Цифра | Источник |
|---|---|

## Вопросы к автору
- ...
```

автору в чат: пост целиком, три лучшие первые строки и вопросы, если есть. Готовый текст положить в буфер обмена (`Set-Clipboard` в PowerShell). Дальше ждать его правок или «да».

### 9. После «да»

- Новые подтверждённые факты дописать в `~/linkedin/profile.md`.
- Публикация отдельным шагом через браузер по `README.md` («Как работать с профилем через браузер»), затем запись в `опубликовано.md`.
- Правки автора к черновику сравнить с тем, что выдал бот: если одна и та же правка повторяется во втором черновике, дописать его правилом в этот навык.
