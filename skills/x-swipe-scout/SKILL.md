# Swipe File Scout для X

Пайплайн: `README.md` репозитория. Платформа X фиксирована: если что-то не работает, чинить доступ к X, а не переключаться на LinkedIn или Threads.

## Что где лежит

| Что | Где |
|---|---|
| X List «swipe», приватный | `<ссылка на ваш X List>` |
| Авторы со статусами | `~/linkedin/x-авторы.md` |
| Закладки | https://x.com/i/bookmarks |
| Факты о автору | `~/linkedin/profile.md` (чего там нет, того в идеях нет) |
| Позиционирование и рубрики | `~/linkedin/README.md`, `~/linkedin/план-постов-2-недели.md` |
| Нормы авторов | `~/linkedin/swipe/нормы.json` |
| Разобранные закладки | `~/linkedin/swipe/закладки.txt` |
| Сводка | `~/linkedin/swipe/ГГГГ-ММ-ДД.md` (дата запуска) |

## Правила

- Только чтение. Не нажимать Like, Repost, Follow, Reply, Bookmark и ничего в меню поста. Разрешено: открыть страницу, прокрутить, прочитать DOM.
- Один проход за запуск, пауза 2-3 секунды между прокрутками, не больше 20 прокруток на страницу.
- Чужие посты не копировать целиком: в файл идёт первая строка дословно и пересказ остального в одну строку.
- Рынки из `~/linkedin/README.md` (в образце: США и Китай; русскоязычные посты пропускать).
- Сводка короткая: 5-10 постов. Лучше 5 сильных, чем 10 средних.

## Шаги

### 1. Браузер

Загрузить инструменты Claude in Chrome одним вызовом ToolSearch (`tabs_context_mcp`, `tabs_create_mcp`, `navigate`, `computer`, `javascript_tool`, `get_page_text`, `tabs_close_mcp`, `browser_batch`). Вызвать `tabs_context_mcp` с `createIfEmpty: true` и работать в своей вкладке.

Открыть список. Если X просит войти или показывает пустую страницу без постов, записать в файл сводки одну строку «X: нет входа в аккаунт, сводка не собрана» и остановиться. Пароль не вводить никогда.

### 2. Собрать посты из списка

Открыть `<ссылка на ваш X List>`, подождать 6 секунд. Затем по кругу: выполнить сборщик (ниже) и прокрутить в том же вызове через `window.scrollBy(0, 3000)`, подождать 3 секунды. Остановиться, когда самый старый собственный пост (не репост) старше 24 часов или прошло 30 прокруток.

Уроки первого прогона (23.10.2026):
- Прокрутку делать через JS, не через `computer scroll`, и не больше 5 прокруток в одном `browser_batch`: длинный пакет не дождался ответа.
- У репоста стоит дата оригинала, поэтому для остановки смотреть только на собственные посты.
- 20 прокруток покрыли 18,5 часа (114 постов), отсюда лимит 30.
- Ответ `javascript_tool` обрезается примерно на 2 000 знаков: отбор и подсчёт делать в странице и возвращать короткие строки, тексты забирать по 5 штук.
- Текст со ссылками блокируется («Cookie/query string data»): перед выводом заменять ссылки на `[link]`.
- Длинные посты в ленте обрезаны «Show more»: для разбора хватает начала.
- Сборщик определяется в `window.__col` один раз и живёт до перехода на другую страницу; нормы и данные забрать до закрытия вкладки.

Сборщик копит посты в `window.__swipe`, дубли отбрасывает по ссылке:

```js
(()=>{window.__swipe=window.__swipe||{};
for(const a of document.querySelectorAll('article')){
  const tm=a.querySelector('time'); if(!tm) continue;
  const link=tm.closest('a')?.getAttribute('href')||''; if(!link||window.__swipe[link]) continue;
  const head=a.innerText.slice(0,120);
  const num=id=>{const b=a.querySelector(`[data-testid="${id}"]`);return b?(b.getAttribute('aria-label')||b.innerText||'').replace(/\n/g,' '):''};
  const views=[...a.querySelectorAll('a[href$="/analytics"]')].map(x=>x.getAttribute('aria-label')||x.innerText).join(' ');
  window.__swipe[link]={author:link.split('/')[1],url:'https://x.com'+link,time:tm.getAttribute('datetime'),
    repost:/reposted|сделал(а)? репост/i.test(head), reply:/Replying to|В ответ/i.test(a.innerText.slice(0,200)),
    text:(a.querySelector('[data-testid="tweetText"]')||{}).innerText||'',
    likes:num('like'), replies:num('reply'), reposts:num('retweet'), views};
}
const v=Object.values(window.__swipe);return v.length+' постов, самый старый '+v.map(x=>x.time).sort()[0]})()
```

В конце забрать данные: `JSON.stringify(Object.values(window.__swipe))`. Числа в `aria-label` приходят строкой («1,234 Likes», «1,2 тыс.»): перевести в целые. Множитель (K, M, тыс., млн) искать только сразу после цифры: иначе «k» в слове «Likes» умножает лайки на 1000 (ошибка прогона 23.10).

Если сборщик возвращает 0 постов, разметка X поменялась: сделать скриншот, найти новые селекторы через `read_page`, поправить сборщик в этом файле и записать в сводку, что поменялось.

Сохранить все собранные посты (без отбора, кроме репостов) в `~/linkedin/swipe/raw/ГГГГ-ММ-ДД.json`: массив `{author, url, time, text, likes, replies, reposts}`, лайки уже целыми числами, текст до 500 знаков. Файл читает Trend Bot (`x-trend-bot`), в git он не идёт. Файлы старше 30 дней удалить.

### 3. Закладки

Открыть https://x.com/i/bookmarks (с 23.10 X показывает закладки во вкладке History этой страницы, открыть его), собрать тем же сборщиком (прокрутки до 5). Брать только ссылки, которых нет в `swipe/закладки.txt`, и дописать их туда. Закладки идут в сводку без проверки нормы: их выбрал автор.

### 4. Отбор

1. Выкинуть репосты, ответы, посты старше 24 часов, авторов не из `x-авторы.md` (кроме закладок).
2. Норма автора: медиана лайков по его постам из `нормы.json` (хранить последние 30 значений на автора, туда же дописать сегодняшние посты; формат `{"handle": [лайки, ...]}`, записать до закрытия вкладки). Если у автора меньше 5 значений, норма = медиана лайков его постов в сегодняшнем сборе, а при одном посте отметить «норма неизвестна» и сравнивать с медианой всех собранных постов. Такая кратность у крупных авторов завышена (пример: × 92 у автора с миллионной аудиторией), в таблице писать «норма неизвестна» вместо числа.
   Посты меньше чем с 20 лайками не брать при любой кратности: это шум.
3. Кратность = лайки ÷ норма. Оставить посты с кратностью от 3. Отдельно отметить посты, где ответов больше, чем репостов: такие посты автор считает годными, в них идёт разговор.
4. Выкинуть новости моделей и продуктов без своего мнения автора (пересказ релиза, «X just dropped Y»), розыгрыши и рекламу.
5. Отсортировать по кратности, взять 5-10. Если прошло меньше 5, не добирать слабыми, написать сколько есть.

### 5. Разбор каждого поста

- **Первая строка**: дословно, до первого переноса или 200 знаков.
- **Тип первой строки**: цифра, спор, история, список, вопрос, контраст «было / стало», совет.
- **Формат**: короткий пост, тред, список, картинка, видео, скриншот.
- **Почему сработал**: одна фраза, по фактам (цифра в первой строке, понятный враг, конкретный инструмент), без «цепляет» и «вызывает эмоции».
- **Идея для автора**: тема его поста в LinkedIn по одной из его рубрик (ИИ-поиск и GEO, ИИ-контент и инструменты, стартапы, Китай, путь) и факт из `~/linkedin/profile.md` или `~/linkedin/проверка-источников.md`, на который он опирается. Нет подходящего факта: написать «факта нет, спросить у автора», не придумывать.

### 7. Раз в неделю (понедельник)

- Кого добавить: авторы, чьи посты участники списка репостили 3 и больше раз за неделю (смотреть репосты в сборах недели). Проверить профиль: пишет по-английски, был пост за 30 дней, в теме автора.
- Кого убрать: авторы без постов в сборах за 14 дней.
- Предложить списком в разделе «Для списка». Список в X и `x-авторы.md` меняет только автор или агент после его «да».

### 8. Конец

Закрыть свою вкладку. Ответить автору одной-двумя строками: сколько постов в сводке, самый сильный (автор и кратность) и путь к файлу. Если запуск по расписанию, ответ не нужен, достаточно файла.
